Updated: 7.17.26 — switched from pilxi's generic PIFGLX_* card interface to
the vendor-supplied pi620lx wrapper (Pickering support confirmed this is the
correct methodology for the 41-620 cards in this chassis; see `test01` in
this directory, the sample script they provided). pilxi is still used to open
the LXI session itself, but no PIFGLX_* calls or Pi_Session.OpenCard() calls
are made anymore.

The pickeringInterface.py handles all interfacing to update the waveforms generated by the function generators. It consists of two main functions, initPXIE() and updateWaveform().
NOTE: You MUST install the Pickering Direct IO drivers to your machine they are located in this repo under \PickeringManuals\Pickering_PXI_Driver_Package. This set of drivers handles the conversion from the C wrapper that is the python package to the IO interfacing.

- initPXIE() - Run this function in the main loop, will locate and initilize the connection with the pickering cabinet and saves the bus locations and typing of the cards in the connection.
    - RETURNS - (session, waveforms) tuple. `session` is the pilxi.Pi_Session used to obtain the LXI session ID that pi620lx.Base is built from — the caller MUST keep a reference to it for as long as the cards are used. Pi_Session.__del__ disconnects the LXI session, which invalidates every card opened from it, so letting `session` go out of scope (e.g. not storing the return value) causes the cards to fail shortly after garbage collection. `waveforms` is the array of waveAtributes; each card object is stamped with `_bus`/`_device` attributes (there is no CardId()/CardLoc() on a pi620lx.Card).
    - Card discovery goes through `pi620lx.Base.findCards()`, which is 41-620-specific — every card it returns is already known to be a 41-620 function generator, unlike the old pilxi.Pi_Session.FindFreeCards() approach (which returned every free card in the chassis regardless of type, requiring a CardId() substring check afterward). There is also no "free vs claimed" concept exposed by this API to check against — findCards() is the only signal available.

### Card interface (pi620lx.Card)

Cards are configured one channel at a time: `card.setActiveChannel(channel)` selects the channel, and subsequent calls (setTriggerMode, setOutputOffsetVoltage, setAttenuation, generateSignal, outputOn/outputOff) apply to whichever channel is currently active. There is no per-call channel argument like the old `PIFGLX_SetFrequency(channel, freq)` style.

pi620lx.Card has **no PIFGLX_Get*-equivalent read-back calls** — you cannot read live frequency/amplitude/offset/phase/generating-state back from hardware the way the old pilxi-based code could (`readChannelStatus()` and the "Generator Status (live hardware read-back)" table in `groundController.py`'s LXI Manager window were removed for this reason). All status displays now show only the last-commanded (software-cached) value.

pi620lx.Card also has no CardId()/CardLoc() — card identity for logging/health-check purposes uses the `_bus`/`_device` attributes initPXIE() stamps onto each card, and `card.revisionQuery()` is used in place of CardId() as a lightweight liveness ping.

- updateWaveform(card, wave) — configures `channel` on `card` per `wave` (a waveAtributes) and starts generation.
    - RETURNS - None
    - Sequence: setActiveChannel → outputOff → setTriggerMode(FRONT, CONT) → setOutputOffsetVoltage → setAttenuation → generateSignal(..., generate=False) → outputOn.
    - **Unit/semantic changes from the old pilxi-based version:**
      - `frequency` on waveAtributes is still Hz; updateWaveform() converts it to kHz before calling `card.generateSignal()`, per test01's convention. This conversion is trusted from the sample script's comment, not independently verified against the driver — worth confirming against real hardware.
      - `amplitude` is now **dB of attenuation** (`card.setAttenuation()`), not a target voltage — pi620lx's documented workflow has no direct "set amplitude in volts" call. Any existing CSV configs written under the old volts-based semantics need their `amplitude` column values reinterpreted/redone as dB.
      - `offset` is a voltage in the range **-5 to 5V** (`card.setOutputOffsetVoltage()`) — the old range check was 0-5V, which was a bug relative to test01's documented -5 to 5V range; this is now fixed.
      - `symmetry` (0-100) is a new waveAtributes field, required by `card.generateSignal()`. Defaults to 50 if not set; the CSV loader (`readConfigs()`) treats it as an optional column, also defaulting to 50 when absent.
      - Waveform types: only SINE (0), TRIANGLE (1), SQUARE (2) are supported (`pi620lx.Card.signalShapes`) — note TRIANGLE/SQUARE are swapped relative to the old `pilxi.WaveformTypes` enum values. RAMP/DC/PULSE/PWM/ARB have no pi620lx equivalent and are no longer supported; an unrecognized/unsupported `waveform_type` in a CSV falls back to SINE.

- abortGeneration(card, channel) — replaces the old direct `card.PIFGLX_AbortGeneration(channel)` calls (pi620lx has no equivalent method). Selects the channel and switches its output off.

- waveformSelfCheck(cards) — write-only smoke test now (writes known values to channel 1 of each card and checks whether the write raised an error). It can no longer read values back and compare, since pi620lx has no PIFGLX_Get* calls — a card that silently ignores a bad write will still report PASSED.
